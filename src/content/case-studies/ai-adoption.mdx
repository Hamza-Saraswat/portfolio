## Context

I joined FieldPulse in October 2025. The company was interested in AI in the way most companies are interested in AI: enthusiastic, with a handful of people paying for their own tools and quietly getting good at them.

What did not exist was any shared surface. No internal patterns, no documented context for models to work from, no path from "I tried something that worked" to "the team can use this." Every person's usage was a private experiment that died when they closed the tab.

## Problem

The instinct in that situation is to build an impressive demo. It is the wrong instinct — a demo proves a model can do something, not that an organisation can rely on it.

The actual blockers were structural:

- Knowledge was scattered across a help center, a wiki, and people's heads, in formats nothing could query.
- There was no internal documentation written for machines to consume, so anything built started from zero context.
- There was no example of an AI system running in production with real users, which meant no shared reference for what "good" looked like.
- There was no route from a working prototype to something a team would depend on.

## Approach

  src={adoptionLayers}
  alt="Three infrastructure layers feeding the systems built on them, and where those landed"
  caption="Three layers, built in order. Each one made the next one cheaper."
/>

Three layers, deliberately in this order.

**A shared prompt library.** A searchable internal library of vetted prompts and workflows, so that the person who worked out a good approach on Tuesday was not the only beneficiary of it. The point was not the prompts — it was making good practice visible and copyable by default.

**Machine-readable internal documentation.** API documentation and a packaged skill that gave coding agents real context about how FieldPulse systems actually work. This is unglamorous and it is the highest-leverage thing on the list: every agent built afterwards started from an informed position instead of guessing.

**An agent foundation.** A reference architecture for connecting an agent to live documentation through MCP, rather than each project reinventing retrieval. The [internal knowledge assistant](/work/internal-knowledge-assistant/) was the first system built on it, and it became the internal proof that this class of tool could run in production and be trusted.

## Outcome

The clearest measure is that AI work at FieldPulse is now something the company operates rather than something individuals try.

**Two agents run in production.** The [support inbox agent](/work/support-inbox-agent/) drafts first responses on the live support inbox. The [internal knowledge assistant](/work/internal-knowledge-assistant/) answers product questions in Slack, and has handled 1,090 of them across eleven weeks.

**The patterns are reused rather than rebuilt.** The support agent became a platform hosting a second, unrelated [payments agent](/work/payments-operations-agent/) as an isolated brain on the same chassis. The [customer status pages](/work/customer-status-pages/) reuse the same guardrail-and-evaluation pattern for public output.

**Evaluation is normal now.** Braintrust suites, golden-fixture harnesses, adversarial gate tests, shadow runs, and one hand-audit of 422 answers. That is the thing I would most want to be judged on, because it is the difference between a demo and a system.

**The build process itself changed.** The [onboarding platform](/work/onboarding-platform/) was shipped with fleets of parallel coding agents governed by written playbooks and phase discipline — three repositories, 97 tests, in production.

## What I'd do differently

**Measure the baseline before changing anything.** I have good numbers for what these systems do now and almost nothing about what came before them. Nobody was going to thank me for spending my first month measuring how long knowledge lookups took, and it would have made every claim since then far stronger.

**Publish honest numbers earlier, and design metrics that are hard to game.** The accuracy audit on the internal assistant corrected a number I had been reporting for months. The correction was worth doing, and it should not have taken months. The pattern I would set up on day one: a small sample, graded by hand, every week, from the very first week.

**Push harder on the boring layer.** The machine-readable documentation was the highest-leverage thing built and the one I treated as a prerequisite rather than a product. It deserved the same care and maintenance as the agents that consume it.

**Write down what we decided not to build.** Several things were correctly rejected — a self-hosted retrieval platform, an auto-send stage that was built and deliberately left switched off, two payments categories ruled permanently out of scope. Those decisions are institutional knowledge, and they were mostly recorded in my own head rather than anywhere a colleague could find them.
